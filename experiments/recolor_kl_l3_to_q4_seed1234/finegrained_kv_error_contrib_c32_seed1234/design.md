我建议下一步做一个专门的实验：异构 KV 的细粒度误差分布与功能敏感性分析（Fine-grained KV Error & Functional Sensitivity Analysis）。

这次先不训练新的 Translator。我们的目标是把当前层敏感性实验中最重要的两个问题区分开：

1. 某些层效果差，是因为它们的 K/V 翻译误差本身更大吗？
2. 还是误差大小相近，但 Receiver 对这些误差更加敏感？

这两个问题一旦区分清楚，后续才知道该优化翻译精度，还是优化功能敏感方向。

## 二、实验一：构建逐维度 KV 误差图谱

这是当前最需要补充的部分。

对于第 \\(l\\) 层、第 \\(h\\) 个 KV Head、第 \\(t\\) 个 Token、第 \\(d\\) 个维度，记录：

\\[ \Delta K\_{l,h,t,d} = K^T\_{l,h,t,d}-K^N\_{l,h,t,d} \\]

同时记录：

\\[ E\_{l,h,t,d}=|\Delta K\_{l,h,t,d}| \\]

对于 V 做完全相同的计算。

这样，单道题的误差数据就保留为：

\\[ E_K,E_V\in\mathbb{R}^{L\times H\_{KV}\times T\times d} \\]

这与之前六层组的一个 Relative L2 数字不同，我们不再一开始就把所有信息平均掉。

具体分析四种现象：

| 分析对象    | 我们要观察什么                |
| ------- | ---------------------- |
| 逐层      | 19–30 层是不是确实有更大的数值误差？  |
| 逐 Head  | 某些 Head 是否长期翻译得不好？     |
| 逐 Token | 是否只有少数关键 Token 出现较大误差？ |
| 逐维度     | 是否存在部分维度持续偏差较大？        |

需要同时记录原始误差和按 Native 参考尺度归一化后的误差，避免不同层、不同维度的数值尺度影响比较。

预期输出：单层、单 Head 的 Token × Dimension 误差图

## 三、实验二：分析每个维度的误差是否影响 Attention

这一阶段是整个实验最关键的地方。

因为对于 K，Receiver 真正使用的不是 K 自身的 L2 距离，而是：

\\[ s_t=\frac{Q^\top K_t}{\sqrt{d_k}} \\]

如果我们固定同一个 Query，那么翻译误差对第 \\(t\\) 个 Token 的 Attention Logit 的影响就是：

\\[ \boxed{ \Delta s_t= \frac{1}{\sqrt{d_k}} \sum\_{d=1}^{d_k}Q_d(K^T\_{t,d}-K^N\_{t,d}) } \\]

这里有一个很重要的变化。

以前我们只关心：

\\[ |K^T\_{t,d}-K^N\_{t,d}| \\]

现在进一步关心：

\\[ \boxed{ C\_{t,d}= \frac{Q_d(K^T\_{t,d}-K^N\_{t,d})}{\sqrt{d_k}} } \\]

这个 \\(C\_{t,d}\\) 是第 \\(d\\) 个维度的 K 翻译误差，对当前 Attention Logit 变化的带符号贡献。

例如：

| 维度 | K 绝对误差 | 对 Attention Logit 的贡献 |
| -- | ------ | --------------------- |
| 1  | 0.80   | +0.02                 |
| 2  | 0.15   | +0.30                 |
| 3  | 0.60   | -0.01                 |
| 4  | 0.20   | -0.25                 |

示意数据。

你会发现：

K 误差最大的维度，不一定是对 Attention 影响最大的维度。

这正是我们之前的 Relative L2 指标无法体现的。

实际计算时，需要使用经过 QNorm/RoPE 的 Query 和处于相同坐标系的 K；对于 Qwen 的 GQA，还必须正确匹配 Query Head 与 KV Head。

此外，单个维度的贡献可能相互抵消，因此还要计算 Softmax 后的 Attention JS 和 Attention Output 差异。

这阶段至少做两套分析：一套固定 Native Q，隔离 K 的作用；另一套使用实际 Translated Cache 产生的 Q，观察真实推理时的变化。

## 四、实验三：用干预验证这些维度是否真的重要

前两阶段仍然主要是相关性分析。

如果我们想证明某些误差维度真正影响模型功能，就需要进行干预。

以某一层、某个 Head 为例，设计下面四组：

| 实验条件                | 操作                            | 目的                    |
| ------------------- | ----------------------------- | --------------------- |
| Baseline            | 完整 Translated K               | 原始效果                  |
| Native K            | 替换整个 Head 的 K                 | 确认该 Head 的可修复空间       |
| Top-error 修复        | 修复 K 绝对误差最大的部分维度              | 测试大数值误差是否重要           |
| Top-contribution 修复 | 修复对 Attention Logit 影响最大的部分维度 | 测试功能敏感性               |
| Random 修复           | 随机修复相同数量的维度                   | 排除单纯增加 Native 信息带来的收益 |

维度修复使用相同预算，例如修复 8 或 16 个维度，并考虑 RoPE 配对及误差规模匹配，避免产生不公平的比较。

同时，不只比较 Accuracy，还要比较标准答案的分数变化、Next-token KL 和 Attention Output。

这里有两个特别重要的判断：

结果 A：Top-error 修复比 Random 明显更有效。

说明大数值误差本身具有一定功能解释能力。

结果 B：Top-contribution 修复明显优于 Top-error。

说明真正需要修复的可能不是误差最大的维度，而是与 Receiver Query 相互作用最强的误差方向。

如果两者都没有改善，那么我们就不能把层敏感性简单解释为某些维度的错误。

## 五、跨任务验证怎么做？

我建议分两轮，而不是一开始把所有组合跑满。

第一轮：机制探索

方法 C，ARC32 + HotpotQA32。所有 36 层都计算逐维度误差图谱，重点研究 1–6、19–24、25–30 层的 Attention 变化和部分维度修复。

第二轮：独立验证

加入 A/D 方法，覆盖 ARC 与 HotpotQA，并使用未参与维度选择和规则设计的样本检验。之后再扩展 MMLU-Pro，判断规律是否跨任务成立。

验证时需要提前固定维度选择规则，不允许每道题使用 Native 答案挑选最有效的维度后，再把结果当成可部署的方法。

另外，我们可以使用现有的 `Engine.cache()`、`native_cache()` 和 Oracle `replace()` 逻辑，不需要重写异构翻译流水线。注意 Native KV 只作为离线诊断和 Oracle 干预使用。

考虑到目前只有一张 V100，建议逐样本流式计算，只保存误差统计量、关键 Token 的完整维度数组和代表性热力图数据，不必把整个数据集的所有 KV 张量长期保存在显存或磁盘中。

## 六、这次实验最终应该交付什么？

我认为应该产出三个结果。

| 产出                                         | 核心问题                 |
| ------------------------------------------ | -------------------- |
| 逐层、逐 Head、逐 Token、逐维度误差图谱                  | 哪些位置翻译得不好？           |
| 数值误差与 Attention 功能误差的关联分析                  | 数值误差能否解释功能损害？        |
| Top-error / Top-contribution / Random 修复对照 | 修复功能敏感误差是否比修复大误差更有效？ |

最后一个对照尤其重要，因为如果它能在不同任务上稳定成立，我们才有充分理由设计一个新的 Function-aware Translator。

### 我最希望先得到的结论

我不急于证明第 19–30 层更重要，而是想回答：

> 对于同一个 Token，翻译 K 的不同维度产生了不同的数值误差。究竟是误差大小，还是误差与 Receiver Query 的相互作用，更能解释最终的功能损害？

这个问题比简单统计“哪些层敏感”更有研究价值。

建议下一步先实现实验一和实验二，暂时不做大规模维度干预。 先用 C 方法在 ARC32 和 HotpotQA32 上输出逐维度误差以及对应的 Attention Logit 贡献，确认我们能否找到具有稳定解释力的现象，再开展实验三。
