# New Stage B: full-vocabulary token KL + gold CE + training views

Reuse and freeze the original MCQ Stage A `runs/mcq/stage_a/best.pt` (validation-selected epoch 2, step 512). Initialize a fresh rank-64 residual KV adapter; do not load the old Stage B. Both Llama and Qwen remain frozen. No Stage A retraining or receiver LoRA is performed.

The requested scheme 3 is the only training run: token-level full-vocabulary forward KL from native Qwen to translated-KV Qwen, plus 0.1 times gold-answer token CE. Teacher and student use identical Qwen answer-prefix tokens. KL is averaged over all candidate-answer token positions, and CE over the correct answer's token positions. No candidate-only KL, EOS loss, generated rationale or student rollout is added. Single-token candidates share the same next-token distribution; evaluating it once gives exactly the same averaged KL.

Retain the original 2048 training questions and 256 held-out validation questions from OBQA and ARC. Four epochs have 2048 question-view draws each, with effective batch 8, 1024 total optimizer updates, learning rate 1e-4 and gradient clip 30. Every training question gets two original-text visits and two letter visits. The letter visits use one 0-shot and one 5-shot prompt with independently permuted choices and remapped gold labels. Demonstrations come only from the same task's original training subset and exclude the current question. The letter layout follows the installed official MMLU template, with a training-only science description; variable-choice ARC questions extend that layout without discarding options. These are training augmentations, not changes to official benchmark prompts.

Validation evaluates both views of all 256 original validation questions with fixed permutations and training-only demonstrations. Its mean token KL + 0.1 gold CE selects the checkpoint. MMLU is evaluation-only. After training, run installed lm-eval 0.4.12 on the unchanged 128-question OBQA and ARC pilots and the existing 128-question, 57-subject, 5-shot MMLU pilot. Reuse native, Stage A and old Stage B baselines, and verify that every benchmark question, prompt and candidate matches the old run. These are pilot metrics, not full benchmark results.

Preserve provenance hashes, prepared views, gradients/loss logs, resumable Stage B states, selected checkpoints and raw per-question evaluation outputs. No KV tensor cache is stored on disk. Old checkpoints/results are untouched. Run CPU tests and preparation, then a longest text/5-shot-letter GPU backward/update smoke check. The smoke-updated adapter is discarded. Launch `run_pipeline.py` with the server B attnkv Python for automatic training and evaluation; inspect `logs/pipeline.log` when needed.
