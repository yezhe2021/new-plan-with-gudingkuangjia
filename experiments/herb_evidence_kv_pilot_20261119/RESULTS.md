192 token 上限的生成由人工逐项核对。客户 ID 要精确，根因需要给出比题干更具体的机制，修复需要说出关键改动。允许同义表述，附带测试、监控等次要细节可省略。词元 F1 和 NLL 用于辅助比较。四组整段 EM 都为 0，原生组输出通常包含标题、列表或额外细节。参考答案 NLL 的排序与生成事实得分相反。NLL 是固定参考措辞下的 teacher-forcing 指标，分数受参考答案开头与模型自由生成风格影响。

## 缓存预检和截断复核

- Text Oracle 与 Native KV 在 8/8 题的整段生成 token 完全相同。固定续写预检的最大 logit 绝对差为 0.15625，单题最大平均全词表 KL 为 0.000569。Native KV 走翻译注入器后的相应上界为 0.109375 和 0.000242。两项预检的所有位置 top-1 一致。
- 96 token 初跑时，A/B/C/D 有 6/4/4/7 题触顶未终止。复跑保持题目、提示和权重一致，192 token 的每条输出均以初跑 token 序列开头。自然终止的 7 道翻译组输出也没有答对任何一项。
- 证据前缀的 Qwen prefill 长度为 213–265 token，含模板。对齐后、应用 RoPE 前的逐题 NMSE 均值为 K 0.1265、V 0.6147。数值误差本身不足以定位造成事实缺失的层、位置或机制。

## 逐题人工核对

每格依次为客户 ID、根因和修复，`1` 表示达到标准。

| herb_03 | 手动操作产生日志重复 | 001 | 111 | 000 |

- `herb_01` 原生组返回 `CUST-0088`，并解释同步生成阻塞 UI 线程、修复改为异步。翻译组把 ActionGenie 描述成游戏并称参考材料缺少事故详情。
- `herb_03` 原生组找出了网络重试触发重复写入。Q-only 猜到了单次写入及去重，客户 ID 错误，也遗漏了重试机制。翻译组明确称证据不足。
- `herb_06` 两个原生组都给出了正确客户 ID 和聚合前归一化时间戳的修复。根因句只重述跨时区聚合错误，未明确当时缺少时间戳归一化，因此根因判 0。
- `herb_07` 两个原生组给出过期统计信息和缺少索引。翻译组只重述查询计划低效，并称修复细节未知。

这次试跑将功能损失定位到冻结异构 KV 路径。原生读取和缓存注入验收通过。同一前缀内的两类证据由一个 Sender 联合编码，结果只覆盖这一 checkpoint 和 8 道人工编写题。当前对照无法分离跨模型 token 对齐、翻译表示质量和接收端读取适配各自的影响。
